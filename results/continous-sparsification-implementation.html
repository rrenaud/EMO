1Context & goal

EMO models can be pruned to a small task-specific subset of experts while keeping most of their accuracy. The repo already ships three selection methods, each of which emits a structurally-pruned model plus a pruning_metadata.json:

  • greedy layerwise — src/hf_training/greedy_prune_layerwise.py (and _variable.py)
  • easy_ep (one-shot output-aware scoring) — src/hf_training/easy_ep_prune.py
  • random baseline — src/hf_training/random_prune.py

All three score experts cheaply (≈ one forward pass) and cut by frequency / importance. This plan adds a fourth method based on Continuous Sparsification (CS). Instead of scoring from a passive forward pass, CS attaches a learnable logit to each routed expert, gates the expert by a soft mask, freezes all model weights, and runs a short calibration loop that trains only those mask logits (plus an L1 sparsity penalty) while annealing a temperature upward. The soft mask hardens toward a boolean decision, which is then baked into a structural prune via the existing in-place prune kernel — producing the exact same artifact the other methods produce, so it drops straight into the existing finetune / eval pipeline.

Why bother: selection becomes loss-aware and jointly optimized across experts and layers, rather than greedy or frequency-based — which may push out the memory / accuracy Pareto frontier.

2The CS algorithm (Savarese et al. 2020)

CS reframes pruning as continuous optimization. Every maskable unit i gets a learnable real-valued logit si. During training the unit is gated by a temperature-scaled sigmoid (a smooth relaxation of the Heaviside step):

soft gate σ(β·si) = 1 / (1 + e−β si)

The objective adds an L1 penalty on the (soft) gates, encouraging them toward 0:

objective ℒ(w, s) = ℒtask( w · σ(β s) ) + λ ∑i σ(β si)

The temperature β is annealed from small (~1) to large (~100–200) over training. As β → ∞, σ(β si) approaches the step function H(si) = 1 if si > 0 else 0 — so the continuous gate hardens into a binary mask. At the end you take H(s) and bake it in.

3Mapping CS onto EMO expert selection

We move the mask from individual weights to whole routed experts. A standard MoE layer output for token x is the gated sum over the top-k selected experts:

baseline MoE y = ∑e ∈ TopK G(x)e · Ee(x)

CS attaches a per-expert mask logit se and scales each selected expert's contribution:

CS-gated MoE y = ∑e ∈ TopK G(x)e · σ(β se) · Ee(x)

The calibration phase freezes the experts Ee and the router, and trains only the se on a small task calibration set, with the L1 penalty sized by λ to drive unimportant experts off. Shared (always-active) experts are not masked — their gate is fixed at 1, so they are never pruned.

4Hardening → how it's used at inference

Yes — the optimization hardens into a boolean mask, but with one important nuance: we do not carry the mask (a per-expert multiply) into inference. We compile the boolean decision into structural pruning — experts with mask 0 have their MLP weights and gate rows physically removed via prune_moe_layer_inplace. So the deployed model is a genuinely smaller MoE, byte-identical in form to what layerwise/easy_ep produce, with zero inference overhead. The mask is a training-time scaffold, not a runtime artifact.

There are two ways to turn the learned masks into the final cut (see tradeoff #1): the pure CS threshold (keep se ≥ 0, emergent count) or CS-as-scorer (use se as an importance score and take top-k to hit an exact budget). Both end in a physically pruned model; we support both behind a flag.

5Tradeoffs

#TradeoffWhat it means here
1Exact budget vs. emergent count Pure CS doesn't let you dial “keep exactly 32.” The penalty λ trades task loss against survivor count, which is emergent — you'd tune λ across runs to land on a target. The escape hatch is to treat se as an importance score and take top-k (exact budget) — trading CS's self-determined sparsity for clean integration with the existing keep_k pipeline. This is the central tension.
2Train-soft / infer-hard rounding gap Mid-training an expert can contribute a partial 0.4× output; at inference you round to {0,1}. If β isn't annealed high enough, the soft model the optimizer tuned diverges from the hard model you deploy. Annealing β high closes the gap — but too fast/high too early saturates the sigmoid, gradients vanish, and masks freeze at init. The β-schedule is a real, sensitive hyperparameter (the one-shot methods have none).
3Cost Layerwise/easy_ep are ≈ one forward pass — effectively instant. CS needs a real optimization loop (forward+backward over calibration data with β/λ schedules). The payoff is a potentially better Pareto frontier from loss-aware, joint selection.
4Top-k limits the gradient In the faithful output-scaling variant an expert's mask only gets a task gradient when it's in some token's top-k; the penalty alone pushes the rest off. The mask can't observe how dropping a selected expert would reroute tokens (top-k membership is fixed). The routing-aware variant addresses this at the cost of complexity.
5This pipeline is forgiving After hardening + physical prune, the existing flow finetunes the survivors (finetune.py). A small rounding gap gets recovered downstream — CS is more forgiving here than in a prune-and-freeze setting.

7Decisions (confirmed)

  • Selection mode: --selection-mode {per_layer, global, threshold} — all three.
  • Mask injection: faithful output-scaling (multiply selected experts' routing weight by σ(β se) after top-k) is the shipped path; routing-aware score-masking documented as a future extension only.
  • Orchestration: standalone pruning script (emits pruned model + metadata); an optional hf_finetune_with_selective_continuous.sh wrapper is sketched, not required.

8Implementation

New file: src/hf_training/continuous_sparsify_prune.py

Mirror the CLI / structure of greedy_prune_layerwise_variable.py. Reuse its imports, prune_moe_layer_inplace, _is_moe_layer, and the save/metadata block where possible.

(a) Mask attachment + monkeypatch

Walk model.model.layers; for each MoE layer register a trainable nn.Parameter cs_mask_logits of shape (num_standard,) where num_standard = num_experts − num_shared_experts, init to a small positive constant s_init (so σ(β0·s_init) ≈ 1 — all experts start fully on). Store a mutable cs_beta (python float, updated per step) on the block. Replace each block's .forward with a bound method (types.MethodType) that reimplements the known forward with one change — right after routing_weights / selected_experts are computed and before the expert loop: 

full_mask = torch.cat([
    torch.sigmoid(self.cs_beta * self.cs_mask_logits),                    # standard experts
    torch.ones(self.num_shared_experts, device=dev, dtype=torch.float),   # shared: fixed at 1
])                                                                        # -> (num_experts,)
routing_weights = routing_weights * full_mask[selected_experts].to(routing_weights.dtype)

The no-shared path simply has full_mask = σ(β s) over all experts. Shared positions are gathered at 1 so they are never pruned. The patched forward must preserve the (final_hidden_states, router_logits) return tuple and the always_active_experts / norm_topk_prob branches. Keep a handle to restore the original forward after calibration.

(b) Freeze + optimizer

for p in model.parameters(): p.requires_grad_(False)
mask_params = [blk.cs_mask_logits for blk in moe_blocks]
for m in mask_params: m.requires_grad_(True)
opt = torch.optim.Adam(mask_params, lr=args.lr)

(c) Calibration loop (manual, single-process)

Build a DataLoader from load_finetuning_dataset(...) + MaskedLossDataCollator. Subsample with --num-calibration + --prune-seed (mirror the seeded torch.randperm subsampling in greedy_prune_layerwise.py). Per step:

  1. Forward model(input_ids, attention_mask=...); compute CE manually from logits + shifted labels (ignore_index=−100) — avoids contaminating the loss with the model's router aux loss.
  2. penalty = λ · ∑layers ∑e σ(β se) computed directly from the params (so even never-selected experts get pushed off).
  3. loss = ce + penalty; backward; clip_grad_norm_; opt.step().
  4. Update β on every block via an exponential schedule from --beta-start to --beta-end across the planned step count.
  5. Log: mean mask, fraction of se≥0, ce, penalty.

(d) Selection → keep-set

After the loop, read per-layer se. Final score = se (monotonic in σ). Build experts_kept_per_layer, always appending the num_shared trailing shared indices (as the other methods do):

  • per_layer: top (keep_k − num_shared) standard experts each layer → uniform keep_k.
  • global: rank all standard experts across MoE layers; keep total (keep_k − num_shared) × num_moe_layers; per-layer counts vary (use the variable save path → keep_k_per_layer).
  • threshold: keep standard experts with se ≥ 0 (emergent count, pure CS). Log resulting per-layer counts since they aren't budget-controlled.

(e) Bake + save

Restore the original forward, then for each layer call prune_moe_layer_inplace(layer, experts_to_keep, layer_keep_k, target_shared). Reuse the config-update + save_pretrained + pruning_metadata.json block from greedy_prune_layerwise_variable.py:274–327, with pruning_method="continuous_sparsification" plus CS hyperparams (lambda, beta_start/end, lr, num_steps, selection_mode, s_init) and experts_kept_per_layer / keep_k_per_layer. Run the same before/after hidden-state sanity check used at greedy_prune_layerwise_variable.py:251–272.

CLI args

Match existing: --model --task --split --prune-keep-k --num-shared-experts --save-path --batch-size --num-calibration --num-shots-override --prune-seed --trust-remote-code. Add CS-specific: --selection-mode --lambda --lr --num-steps (or --num-epochs) --beta-start --beta-end --s-init --max-seq-length --grad-clip.

10Future extension not built

Routing-aware variant. Subtract an annealed −γ·(1−σ(β se)) term from router_logits before top-k, so suppressed experts drop out of the top-k and tokens reroute to survivors during calibration — closer to the deployed pruned model and a fuller realization of CS's “co-optimization” claim, at the cost of harder annealing and binarization.
