1TL;DR

The CS method is fully implemented, verified, and parity-checked. In a matched comparison it underperforms easy_ep on arc_challenge (CS-global 0.334 vs easy_ep 0.535, finetuned). A dedicated diagnostic rules out an implementation bug: the mask logits train healthily (large spread, non-degenerate selection, correct sign). CS is simply a weaker selector than easy_ep at these settings — most plausibly because the shipped output-scaling variant is blind to how pruning reroutes tokens. The highest-value next experiment is the routing-aware variant, which targets exactly that gap.

3Is there a bug? (No — verified)

The poor result prompted a sanity-check diagnostic (cs_diagnostic.py): load the model, run CS calibration, and inspect what the masks actually learned. It rules out the three failure modes that would have indicated a defect.

So the masks move a lot, the selection is non-degenerate, and we keep the experts the optimizer wants on (above-chance overlap with the router-frequency ranking; an inverted sign would be below chance). A “responsive” config (s_init=0, β→15, 300 steps) increases frequency overlap to 0.42 and is more decisive (fewer experts above threshold), but does not find a better set — just a slightly more frequency-aligned one. Conclusion: the code is correct; CS is genuinely the weaker selector at these settings.

4Why CS underperforms

  1. The shipped variant is blind to rerouting (primary suspect). The faithful output-scaling variant multiplies each selected expert's contribution by σ(β se) but leaves top-k routing unchanged. So se learns “how much does down-scaling expert e hurt loss while every other expert still fires as usual” — it never observes that, after pruning, tokens reroute onto the survivors. easy_ep scores at the same full-model operating point but its hand-designed output-aware importance evidently transfers better to the pruned model.
  2. The learned signal is only mildly importance-aligned. Frequency overlap of 0.36–0.42 (vs 0.24 chance) means CS keeps a substantially different set than the high-traffic experts — and that different set is worse for accuracy, not better.
  3. global compounds it. Ranking se across layers (logits that may not be comparable layer-to-layer) spent the budget gutting late layers to 7–8 experts, which is additionally harmful on top of the weaker base selection.

5Next steps (prioritized)

P1Routing-aware variant

The most principled fix and the one CS theory says should matter. Before top-k, subtract an annealed penalty from the router logits so suppressed experts actually fall out of the top-k and tokens reroute onto survivors during calibration:

router_logits′ = router_logits − γ·(1 − σ(β se))
  • Directly attacks reason #1 — the calibration operating point now matches the deployed pruned model.
  • Implementation: a second forward hook on gate (or a thin gate wrapper) that adjusts logits pre-softmax; the per-expert output hooks can stay or be removed. Harder annealing (γ, β schedules) is the cost; binarization is touchier.
  • Decision gate: if routing-aware CS still doesn't reach easy_ep, the formulation — not the implementation — is the ceiling for this model/task, and CS should be shelved for EMO pruning.

P2Finish the hyperparameter sweep

A select→eval (no-finetune) sweep is wired up in run_cs_sweep.sh (paused; completed cells cached, auto-skipped on resume). Remaining cells — per_layer with steps=500, lr=0.3, and β→50 (the “responsive” regime that aligns better with frequency) — quantify whether better mask optimization lifts accuracy. If they all stay ≈ 0.34–0.40, that is strong evidence the output-scaling formulation itself is the ceiling (and motivates P1 over more tuning).

P3Cheaper / secondary ideas

  • More / longer calibration: the responsive config improved frequency alignment; more data + steps may help, but is unlikely to overcome the rerouting blind spot.
  • Constrain global allocation: normalize se within each layer before the global ranking, or impose a per-layer floor, so it can't gut late layers. Only worth it if the base selection becomes competitive.
  • threshold / Pareto study: CS's natural mode is emergent count; sweeping λ traces a memory↔accuracy curve at variable keep_k (not iso-budget), a different comparison than the iso-32 runs here.

6Eval methodology notes

  • Finetune adds ~0.07 here (easy_ep: 0.465 → 0.535). So absolute numbers shift with finetuning, but relative selection quality is preserved — the no-finetune sweep is a valid, ~2× cheaper way to rank selectors; finetune only the winner for the headline number.
  • trust_remote_code must be passed explicitly to launch_eval for raw checkpoint paths: --model-args '{"trust_remote_code": true}'.
  • Disk: df /workspace shows the MFS backing store, not the volume quota; a full volume makes save_pretrained die mid-write (exit 120, looks like OOM). Use du. Each pruned model is ~7.8 GB — delete intermediates between sweep cells.
